## Node.js Support

The minimum supported Node.js version is now `^22.23.5 || ^24.22.3 || >=26.13.1`. Node.js 20, 23 and 25 are no longer supported. Upgrade Node.js before upgrading `listr2`.

## Breaking Changes

Most of these change what the _DefaultRenderer_ prints. They need no code changes, but snapshot tests of the output and anything parsing it may need updating. Three need code changes: the removal of `DefaultRenderer.create()`, the input lock, and option values that now throw.

### Finished tasks are printed while the list runs

The _DefaultRenderer_ prints each task once it finishes, above the tasks still running, instead of redrawing the whole list and printing it again at the end. With the default options, the final output is the same as before, except for the changes below. See [How the Output Updates](../renderer/default.md#how-the-output-updates).

### Concurrent lists are printed in the order their tasks finish

Tasks of a list with the `concurrent` option are printed in the order they finished instead of the order they were declared in.

![A concurrent group with listr2 12](../../examples/screenshots/concurrent.png)

_After: the subtasks in the order they finished._

### `collapseSubtasks: false` prints the final status line after the subtasks

A task with `collapseSubtasks: false` prints its title above its subtasks and its status line, with its title, after them, as the header and the footer of a bracket. See [When Tasks Are Persisted](../renderer/default.md#when-tasks-are-persisted).

```text
// before
✔ Running migrations
  ✔ Running migration 001.
  ✔ Running migration 002.
  ✔ Running migration 003.

// after, while it runs
┌ Running migrations
│ ✔ Running migration 001.
│ ✔ Running migration 002.
│ ⠋ Running migration 003.
└ ❯ Running migrations

// after, once it finished
┌ Running migrations
│ ✔ Running migration 001.
│ ✔ Running migration 002.
│ ✔ Running migration 003.
└ ✔ Running migrations
```

_Before, with `listr2@11.4.1`, while it runs: the title of the task above its subtasks._

![A group with collapseSubtasks: false while it runs with listr2 12](../../examples/screenshots/bracket-running.png)

_After, while it runs: the header above the subtasks and the footer below them._

![A group with collapseSubtasks: false once it finished with listr2 11](../../examples/screenshots/before-bracket.png)

_Before, once it finished: the title of the task with its status above its subtasks._

![A group with collapseSubtasks: false once it finished with listr2 12](../../examples/screenshots/bracket.png)

_After, once it finished: the footer below the subtasks shows the status and the title._

### Expanded subtasks are drawn as a bracket

Every task that shows its subtasks under its title draws a bracket: a header with its title and a dimmed `│` in front of its subtasks. The status icon shows on the header while the header can still change, and the bracket closes on its last line. A group with `collapseSubtasks: false` that has printed its header, or whose header does not fit on the terminal, shows the status and the title on a footer instead. A task whose subtasks collapse and finish without a problem is still printed as a single line. Change the glyphs through the `icon` and `color` renderer options with the `ListrDefaultRendererLogLevels.CONNECTOR_START`, `CONNECTOR` and `CONNECTOR_END` keys, or set `markIndentation: false` to draw no bracket. See [Brackets](../renderer/default.md#brackets).

```text
// before
⚠ Validating config
  ✔ Validating package.json.
  ✖ compilerOptions.target is missing.

// after
┌ ⚠ Validating config
│ ✔ Validating package.json.
└ ✖ compilerOptions.target is missing.
```

![Two groups expanded by a failed subtask with listr2 12](../../examples/screenshots/failure.png)

### Lists taller than the terminal are summarized while they run

While the running part of the list is taller than the terminal, finished subtasks are folded into a `↑ N` line and waiting tasks into a `… N` line. The final output is unchanged. Change their icons with the `ListrDefaultRendererLogLevels.SUMMARY_COMPLETED` and `SUMMARY_WAITING` keys. See [Taller Than the Terminal](../renderer/default.md#taller-than-the-terminal).

![A list taller than the terminal while it runs](../../examples/screenshots/summary.png)

_A list taller than a terminal of 12 rows while it runs._

### Output written to `stdout` and `stderr` appears as it arrives

Anything written to `process.stdout` or `process.stderr` while the _DefaultRenderer_ runs is printed above the task list as it arrives, instead of after the task list once the run has finished.

### _ProcessOutput_ no longer buffers captured output until the release

What is still captured when the output is released is written in the order it arrived, without an empty line before it.

- The `leaveEmptyLine` option of `ProcessOutput` is removed.
- `ProcessOutputStream.take()` is removed. `ProcessOutputStream.hijack()` takes a callback that receives each write as text, and `ProcessOutputStream.release()` returns nothing.
- `ProcessOutputBuffer` no longer takes the `stream` option, and its entries no longer carry a `stream`.
- The `dump` option of `ProcessOutput` still drops the captured output of the streams it leaves out.

### Keyboard input is not shown while the tasks run

What you type while the _DefaultRenderer_ runs is not shown, and reaches the shell after the run. `Ctrl+C`, `Ctrl+\`, `Ctrl+Z` and prompts work as before. Set the renderer option `lockInput: false` when a task reads the terminal input itself, such as a child process spawned with `stdio: 'inherit'`. See [Keyboard Input](../renderer/default.md#keyboard-input).

### `DefaultRenderer.create()` is removed

The public `create()` method of the _DefaultRenderer_, which rendered the whole task list into a string, is removed. A custom renderer that extends the _DefaultRenderer_ and calls it has to render the task list itself.

### Invalid option values throw

These option values now throw a `RangeError` that names the option and the value, when the list or the task is created. A subtask list created with one fails its parent task.

- `concurrent`: `0`, a negative number or `NaN`. They made `run()` hang. `true`, `false`, `Infinity` and positive numbers work as before.
- `retry` and `retry.tries`: a fraction greater than `0`. `0`, a negative number and `NaN` still mean no retries.
- The _DefaultRenderer_ options `indentation` when negative or `NaN`, `formatOutput` when it is neither `truncate` nor `wrap`, and `outputBar` and `bottomBar` when negative or `NaN`.

## Fixes

- `Task.isClosed()`, as seen by renderers, returns `true` once a task has finished, including tasks skipped through the `skip` option. It was never set before.
- When a run is interrupted, the subtasks that never started are marked as cancelled before their parent finishes, instead of being left as waiting.
