## Node.js Support

The minimum supported Node.js version is now `^22.23.5 || ^24.22.3 || >=26.13.1`. Node.js 20, 23 and 25 are no longer supported. Upgrade Node.js before upgrading `listr2`.

## Breaking Changes

Most of these change what the _DefaultRenderer_ prints. They need no code changes, but snapshot tests of the output and anything parsing it may need updating. These need code changes: the removal of `DefaultRenderer.create()`, `DefaultRenderer.format()` taking a column, the changes to _ProcessOutput_, the input lock, and option values that now throw.

### Finished tasks are printed while the list runs

The _DefaultRenderer_ prints each task once it finishes, above the tasks still running, instead of redrawing the whole list and printing it again at the end. A group is printed in one piece once it closes, with its subtasks in the order they were declared in; only the tasks of the top-level list are printed one by one. With the default options, the final output is the same as before, except for the changes below, and except for a subtask that still changes after its group closed, such as in a concurrent list with `exitOnError: false`, which keeps the state it had when the group was printed. See [How the Output Updates](../renderer/default.md#how-the-output-updates).

### Concurrent lists are printed in the order their tasks finish

Tasks of a top-level list with the `concurrent` option are printed in the order they finished instead of the order they were declared in.

![A concurrent list with listr2 12](../../examples/screenshots/concurrent.png)

_The tasks in the order they finished._

### Lists taller than the terminal are summarized while they run

While the running part of the list is taller than the terminal, finished subtasks are folded into a `↑ N` line, and waiting tasks, or running tasks when there are more than the terminal shows, into a `… N` line. The final output is unchanged. Change their icons with the `ListrDefaultRendererLogLevels.SUMMARY_COMPLETED` and `SUMMARY_WAITING` keys. See [Taller Than the Terminal](../renderer/default.md#taller-than-the-terminal).

![A list taller than the terminal while it runs](../../examples/screenshots/summary.png)

_A list taller than a terminal of 12 rows while it runs._

### Output written to `stdout` and `stderr` appears as it arrives

Anything written to `process.stdout` or `process.stderr` while the _DefaultRenderer_ runs is printed above the task list as it arrives, instead of after the task list once the run has finished.

### _ProcessOutput_ no longer buffers captured output until the release

What is still captured when the output is released is written in the order it arrived, without an empty line before it.

- The `leaveEmptyLine` option of `ProcessOutput` is removed.
- `ProcessOutputStream.take()` is removed. `ProcessOutputStream.hijack()` takes a callback that receives each write as text, and `ProcessOutputStream.release()` returns nothing.
- `ProcessOutputBuffer` no longer takes the `stream` option, and its entries no longer carry a `stream`.
- The `dump` option of `ProcessOutput` still drops the captured output of the streams it leaves out.
- The _DefaultRenderer_ calls `update()`, `persist()`, `clear()`, `lockInput()` and `unlockInput()` on the `processOutput` of its logger. A custom _ProcessOutput_ has to provide them, by extending the integrated one.
- While it is hijacked, _ProcessOutput_ registers an exit hook through `signal-exit`, and listeners for `SIGTSTP` and `SIGCONT` while the input is locked, and removes them on the release.

### Keyboard input is not shown while the tasks run

What you type while the _DefaultRenderer_ runs is not shown, and reaches the shell after the run. `Ctrl+C`, `Ctrl+\`, `Ctrl+Z` and prompts work as before, and what you type is shown after `Ctrl+Z`. A run started in a background process group, such as with `&` or under `timeout` or a similar wrapper in a script, stops with `Stopped (tty output)` until it is brought to the foreground; set `lockInput: false` there. Set the renderer option `lockInput: false` when a task reads the terminal input itself, such as a child process spawned with `stdio: 'inherit'`. See [Keyboard Input](../renderer/default.md#keyboard-input).

### `DefaultRenderer.create()` is removed

The public `create()` method of the _DefaultRenderer_, which rendered the whole task list into a string, is removed. A custom renderer that extends the _DefaultRenderer_ and calls it has to render the task list itself.

### `DefaultRenderer.format()` takes a column

The protected `format(message, icon, level)` method of the _DefaultRenderer_ takes the column a line starts at as its last argument, instead of a level of indentation. A custom renderer that calls it with a level passes `level * indentation` instead.

### Invalid option values throw

These option values now throw a `RangeError` that names the option and the value, when the list or the task is created. A subtask list created with one fails its parent task.

- `concurrent`: `0`, a negative number or `NaN`. They made `run()` hang. `true`, `false`, `Infinity` and positive numbers work as before.
- `retry` and `retry.tries`: a fraction greater than `0`. `0`, a negative number and `NaN` still mean no retries.
- The _DefaultRenderer_ options `indentation` when negative or `NaN`, `formatOutput` when it is neither `truncate` nor `wrap`, and `outputBar` and `bottomBar` when negative or `NaN`.
- The options of both the renderer and the fallback renderer are checked, whichever of them runs.
- The `logger` option of every renderer that logs when it is not a _ListrLogger_, and `timer`, `timestamp` and `pausedTimer` when they are not a preset with a `field`.
- The _TestRenderer_ options `state`, `messages` and `messagesToStderr` when they are not a list, and `task` when it is neither `false` nor a list.

## New Features

### Brackets around expanded subtasks

Set the _DefaultRenderer_ option `markIndentation: true` to draw a task that shows its subtasks as a bracket: a header with its status and title, and a dimmed `│` in front of its subtasks, which sit one level deeper than without it. See [`markIndentation`](../renderer/default.md#markindentation).

```text
// markIndentation: false, the default
⚠ Validating config
  ✔ Validating package.json.
  ✖ compilerOptions.target is missing.

// markIndentation: true
┌ ⚠ Validating config
│   ✔ Validating package.json.
└   ✖ compilerOptions.target is missing.
```

## Fixes

- `Task.isClosed()`, as seen by renderers, returns `true` once a task has finished, including tasks skipped through the `skip` option. It was never set before.
- A list that fails with `exitOnError: false` now ends its renderer, calling `renderer.end(error)`, and removes its signal handler, like a list that throws.
- When a run is interrupted, the subtasks that never started are marked as cancelled before their parent finishes, instead of being left as waiting.
