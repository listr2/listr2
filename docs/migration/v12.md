## Node.js Support

The minimum supported Node.js version is now `^22.23.5 || ^24.22.3 || >=26.13.1`: the latest security release of each supported line, as of 2026-11-11. Node.js 20, 23 and 25 are end-of-life and no longer supported, and earlier patch releases of 22, 24 and 26 miss security fixes, some of them for vulnerabilities exploited in the wild. Upgrade Node.js before upgrading `listr2`.

## Breaking Changes

Apart from the removal of `DefaultRenderer.create()`, these change what the _DefaultRenderer_ prints. No code changes are required for them, but snapshot tests of the output and anything parsing it may need updating.

### Finished tasks are persisted while the list runs

The _DefaultRenderer_ no longer redraws the whole task list on every update and prints it again at the end. Tasks that will not change anymore are written once, above a live region that holds everything still running, and scroll into the scrollback of the terminal. Long task lists no longer lose their top, and duplicated lines no longer pile up when the terminal is resized; a resize leaves at most a stale row behind. See [How Updates Are Rendered](../renderer/default.md#how-updates-are-rendered).

With the default options, the final output is the same as before, except for the changes below.

### Concurrent lists are printed in the order their tasks finish

Tasks of a list with the `concurrent` option are persisted as soon as they finish, so the final output shows them in the order they finished instead of the order they were declared in.

### `collapseSubtasks: false` prints the final title line after the subtasks

A task with `collapseSubtasks: false` persists its subtasks as they finish. Its title is persisted with its subtasks still running, and its final title line, with its icon and timer, is printed after its subtasks. A connector in the first column of the subtask indentation links the two title lines, in the persisted and the live part alike. See [When Tasks Are Persisted](../renderer/default.md#when-tasks-are-persisted).

```text
// before
✔ Running migrations [2s]
  ✔ Running migration 001.
  ✔ Running migration 002.
  ✔ Running migration 003.

// after, while it runs
❯ Running migrations
│ ✔ Running migration 001.
│ ✔ Running migration 002.
│ ⠋ Running migration 003.

// after, once it finished
❯ Running migrations
│ ✔ Running migration 001.
│ ✔ Running migration 002.
│ ✔ Running migration 003.
✔ Running migrations [2s]
```

### Lists taller than the terminal are summarized while they run

While the live region is taller than the terminal, the finished subtasks of a task whose subtasks collapse that do not fit are shown as a single `✔ N completed` line until the task closes, and then the tasks that have not started yet and do not fit as a single `◼ N waiting` line. The final output is unchanged, since every task is persisted in full once it finishes. See [Taller Than the Terminal](../renderer/default.md#taller-than-the-terminal).

### Output written to `stdout` and `stderr` appears as it arrives

Anything written to `process.stdout` or `process.stderr` while the _DefaultRenderer_ runs is written above the task list as it arrives, instead of after the task list once the run has finished.

### Keyboard input is not echoed while the tasks run

The _DefaultRenderer_ turns off the echo of the terminal with `stty -echo` while the tasks run, so pressing Enter or typing does not move the task list. What is typed is not shown, and reaches the shell after the run. `Ctrl+C`, `Ctrl+\`, `Ctrl+Z` and prompts work as before. Set the renderer option `lockInput` to `false` when a task reads the terminal input itself, such as a child process spawned with `stdio: 'inherit'`. See [Keyboard Input](../renderer/default.md#keyboard-input).

### `DefaultRenderer.create()` is removed

The public `create()` method of the _DefaultRenderer_, which rendered the whole task list into a string, is removed. The renderer itself no longer used it, and it could not show the tasks that had already been persisted. A custom renderer that extends the _DefaultRenderer_ and calls `create()` has to render the task list itself.

## Fixes

- `task.isClosed()` returns `true` once a task has finished, including tasks skipped through the `skip` option. It was never set before.
- When a run is interrupted, the subtasks that never started are marked as cancelled before their parent finishes, instead of being left as waiting.
